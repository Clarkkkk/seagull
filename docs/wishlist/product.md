## 愿望罐子（Wishlist Jars）PRD v1

本文档描述 Seagull 第一阶段功能：**灵感收集系统（愿望罐子）** 的产品与交互设计，包含功能描述、前端交互（含地图）、以及验收标准。

后端与数据库实现请见：`docs/wishlist/backend.md`。

> 关键变更：不再使用“收件箱 -> 目的地 -> 行程 -> 归档”的非此即彼分层结构。  
> **所有罐子一视同仁**，每个罐子都具备“国家/省/市”字段与“状态”字段；当状态表示“属于某个行程”时，通过 **关联表** 记录与行程的关系。

---

## 目标与范围

### 目标
- 让用户快速把“想去的地点”保存为结构化的“罐子”，并且**必须具备坐标**，为后续行程规划（路线优化、聚类、时间估算）提供可靠输入。
- 支持多种录入入口：地图搜索/选点、系统分享、粘贴链接。
- 支持后续编辑，编辑时以坐标为“真值”，国家/省/市随坐标自动更新。

### MVP 范围（v1）
- 罐子 CRUD（创建/查看/编辑/删除/归档）
- 地图搜索/选点、确认坐标落库
- 链接导入解析（基础可用：提取地点信息 + 地理编码获取坐标）
- 罐子与行程的绑定/解绑（通过关联表）
- 列表筛选：按状态、国家/省/市、关键字

### 非目标（v1 不做）
- 智能聚类/自动生成每日路线（属于行程规划阶段）
- 多人协同编辑
- 批量导入/导出、模板市场
- 复杂去重（仅做轻量提示）

## 核心概念与状态机

### “罐子”的定义
“罐子”是一条结构化的地点灵感记录（POI-like），**坐标必填**，包含名称、地理行政区、来源链接（可选）、备注等。

### 状态（JarStatus）
所有罐子都处于以下三种状态之一：
- **INACTIVE（未活跃）**：默认状态，尚未加入任何行程
- **IN_TRIP（属于某行程）**：已加入某个行程；具体关联关系通过关联表记录
- **ARCHIVED（已归档）**：已归档，不参与默认列表/规划（但可在“归档”中查看/恢复）

> 约束建议：同一时刻一个罐子最多只属于一个行程（v1 简化），因此关联表应保证 **jar_id 唯一**（见后端设计）。

状态迁移（推荐）：
- INACTIVE → IN_TRIP：加入行程
- IN_TRIP → INACTIVE：从行程移除
- INACTIVE/IN_TRIP → ARCHIVED：归档
- ARCHIVED → INACTIVE：从归档恢复（v1 可以支持）

## 功能描述

### 1) 创建罐子
创建入口：
- **地图创建（主入口）**：在地图上搜索地点或选点
- **粘贴链接**：在创建页粘贴 URL
- **系统分享（Share sheet）**：从浏览器/地图 App 分享到 Seagull（Expo）

创建成功后：
- 默认状态：**INACTIVE**
- 立即出现在“愿望罐子列表”中

### 2) 编辑罐子（复用地图界面）
编辑时复用“地图创建”界面：
- 地图以现有坐标定位并显示 marker
- 用户拖动 marker 或重新搜索选点
- **坐标改变时**：自动触发反向地理编码，更新国家/省/市（以坐标为准）

### 3) 归档/恢复
- 归档：将状态置为 ARCHIVED，并从默认列表隐藏
- 恢复：将状态置为 INACTIVE（并清理行程关联）

### 4) 加入/移除行程
操作入口：
- 罐子详情页：选择“加入某行程”
- 行程编辑页：从愿望罐子中挑选加入（后续阶段）

数据规则：
- 加入行程：`status = IN_TRIP`，并在关联表写入一条（jar_id, trip_id）
- 移除行程：删除关联表记录，并设置 `status = INACTIVE`

## 罐子字段定义（产品视角）

### 必填字段
- **名称（name）**：用户可编辑；默认来自地图搜索结果或链接解析结果
- **国家（country）**：随坐标反向解析得到，可展示可编辑（推荐 v1 只读）
- **省/州（province）**：随坐标反向解析得到
- **市（city）**：随坐标反向解析得到
- **坐标（coordinate）**：必须有；包含 `lat`、`lng`（后端统一存储为 WGS-84）

### 可选字段
- **链接（linkUrl）**：来源是链接时建议必填；来源非链接时可为空
- **备注（note）**：用户自由输入

### 建议补充字段（v1 推荐）
- **sourceType**：`MAP` | `LINK` | `SHARE` | `MANUAL`
- **sourceTitle**：链接标题/页面标题（如能解析到）
- **sourceRawText**：分享/粘贴时抓到的原始文本（便于追溯、排错、后续优化解析）
- **placeProvider**：使用的地图服务商标识（如 `google`/`amap`/`mapbox`）
- **placeId**：地图服务商的地点 ID（用于去重、刷新详情、二次拉取）
- **formattedAddress**：结构化地址展示字符串（由地图服务返回）
- **timezone**：由坐标推断（可后续用于行程时间轴/提醒）
- **tags**：简单标签（可后续增强）

> 注：国家/省/市字段与坐标存在“坐标系与行政区映射”问题。建议后端统一以 WGS-84 存储；如采用中国地图服务（GCJ-02），需在边界层做坐标转换，但对 v1 可先在文档中约定“存储 WGS-84”。

## 前端交互设计（Expo）

### 信息架构（页面）
- **愿望罐子列表页**
  - Tab/入口：在“灵感”模块
  - 筛选：状态（未活跃/行程中/已归档）、国家/省/市
  - 搜索：按名称/备注/地址关键字
  - 创建按钮：进入“创建罐子”
- **创建/编辑罐子页（地图复用）**
- **罐子详情页**
  - 显示字段、地图预览
  - 操作：编辑、归档/恢复、加入行程/移除行程

### 创建/编辑页（地图复用）的核心交互
#### 1) 地图搜索 + 选点（必须有坐标）
- **顶部搜索框**
  - 输入关键字 → 调用地图服务的 Place Search/Autocomplete
  - 展示建议列表（名称 + 地址）
- **地图区域**
  - 点击建议项 → 地图定位 + 放置 marker
  - 支持“长按地图”选点（Drop pin）
  - marker 可拖拽（或拖动地图中心 + 固定十字准星）
- **确认按钮（Primary）**
  - 校验：必须有坐标、名称非空
  - 保存后返回详情页或列表页

#### 2) 录入来源为链接（粘贴/系统分享）
流程：
1. 用户粘贴 URL 或从系统分享进入（携带 url/text）
2. 前端调用后端“解析链接”接口（或本地先做轻量提取）
3. 后端返回：
   - 解析出的候选：`name`、`addressText`、可能的 `lat/lng`、`placeId`
4. 若无坐标：
   - 后端调用第三方地图 API（Geocode/Place Search）获取坐标
5. 前端进入“地图确认模式”：
   - 地图定位到解析坐标，marker 可微调
   - 用户确认后保存

校验建议：
- 如果来源是 LINK：`linkUrl` **建议必填**；若解析失败仍允许用户手动在地图上搜索选点后继续保存（保留 `sourceRawText` 便于后续改进解析）。

#### 3) 坐标驱动的行政区更新
当用户移动 marker / 选点成功：
- 触发 **Reverse Geocode**（反向地理编码）
- 更新 `country/province/city/formattedAddress`
- UI 展示为只读字段（v1），避免用户手动改但与坐标不一致

## 边界情况与体验细节

- **解析失败**：链接/分享内容解析不到地址或坐标 → 进入地图页让用户手动搜索选点；保留 `source_raw_text` 便于后续改进。
- **地址歧义**：geocode 返回多个候选 → 前端展示候选列表 + 地图预览，用户选择后再保存。
- **坐标与行政区不一致**：编辑时以坐标为准，国家/省/市自动刷新并覆盖旧值。
- **重复地点**：同一用户创建时若 `place_provider+place_id` 或坐标非常接近（后续）→ 轻提示“可能已保存过”，但允许继续保存（v1）。

## 验收标准（v1）

- 能在 Expo 中通过地图搜索/选点创建罐子，保存后列表可见；详情页展示完整字段。
- 坐标必填：无法在没有坐标时保存。
- 粘贴链接/系统分享可进入导入流程：解析成功自动定位；解析失败可手动选点并保存。
- 编辑复用地图界面：移动 marker 后国家/省/市随坐标更新。
- 罐子可以归档/恢复；可以绑定到某个行程（关联表落库），并可解绑回未活跃。
